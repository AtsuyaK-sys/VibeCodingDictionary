# 設計書：著作権・ライセンス・AIのルール辞典（`licenses.html`）

作成：2026年11月20日　ブランチ：`new/licenses`　状態：設計 → 制作

## 1. なぜ作るか

バイブコーディングでは、**AIが書いたコード・AIが作った画像・ネットで見つけた素材・npm のパッケージ**を組み合わせて、すぐに公開できてしまいます。
「動くもの」は作れても、**使ってよいもの・表示が必要なもの・公開してはいけないもの**を見分ける知識がないまま公開されがちです。生成AIをめぐるルールは2024〜2026年に大きく動いており、今後さらに重要になります。

この辞典は、法律の専門家になるためではなく、**公開ボタンを押す前に「これは確認が必要だ」と気づける**ことを目標にします。

## 2. 対象と前提

| 項目 | 内容 |
|---|---|
| 読者 | AI初心者（Datadreamrs のメンバー）。法律の知識はない前提 |
| 場面 | 個人・小さなチームで、Webサイト・アプリ・Bot・画像や動画を作って公開する |
| 法域 | **日本の法律が中心**。海外（米国・EU）は「違い」として短く触れる |
| 時点 | **2026年11月時点**。変わりやすい内容には時点を書き、`docs/ROADMAP.md` の定期点検リストの対象にする |

## 3. 書き方の方針（正確さのルール）

1. **断定しすぎない。** 法律は「場合による」ことが多い。○ / △ / × の判定には必ず理由と「確かめ方」を付ける。△ を恐れない。
2. **根拠の名前を書く。** 条文（著作権法 第32条 など）、公的な文書（文化庁「AIと著作権に関する考え方について」2024年3月）、判例（最高裁 年月）を、読者が自分で調べられる形で書く。
3. **報道ベースの新しい動きは「報道によると」「○年○月時点」を付ける。** 判決は確定していないものもある。
4. **法律相談ではないことを、ページの冒頭と「困ったとき」タブで明示する。** 迷ったら専門家・公式窓口へ、の導線を必ず置く。
5. **他の辞典と重複させない。** 決済の法律は [決済・収益化辞典](../payments.html)、APIキーは [セキュリティ辞典](../security.html)、素材の入手先は [無料素材辞典](../resources.html) へリンクし、ここでは「権利とルール」だけを扱う。
6. **見本で使う素材・コード・規約文は、すべてこのリポジトリのために作った架空のもの**にする（実在の規約や作品を写さない）。

## 4. 全体の構成（8タブ）

| # | タブ（id） | ねらい | 動く見本 |
|---|---|---|---|
| 1 | 著作権の基本（`basics`） | 何が守られ、何が守られないか | これは著作物？カード ／ 保護期間の計算機 |
| 2 | 他人の作品を使う（`use`） | 引用・リンク・埋め込み・二次創作の線引き | 引用の要件チェッカー ／ 「これ使っていい？」判定 |
| 3 | OSSライセンス（`oss`） | パッケージ・コードを使うときの義務 | ライセンス比較 ／ 使い方別の義務チェッカー |
| 4 | 自分の作品に付ける（`mine`） | 公開するときのライセンスの選び方 | 質問で選ぶチャート ／ LICENSE・表記メーカー |
| 5 | 素材・フォント・音楽（`assets`） | 素材サイトの規約、フォント、BGM | クレジット表記メーカー ／ 規約の読み方 |
| 6 | AIと著作権（`ai`） | 学習・生成・利用の各段階のルール | 2つの段階 ／ 似ている×元を使った 判定 ／ 人の関わりと著作物性 |
| 7 | 個人情報・肖像・商標（`people`） | 著作権以外で問題になる権利 | 「公開して大丈夫？」判定 |
| 8 | 公開前チェックと困ったとき（`check`） | 最終確認と、指摘を受けたときの動き方 | 指摘・削除依頼が来たら（手順送り）＋ チェックリスト |

各タブは他の辞典と同じく「触って理解する（カード）」→「言葉（行）」→「早見表（表）」の順に並べる。すべての項目に日本語の「AIへの指示例」を付ける（付けない項目は理由があるものだけ）。

## 5. タブごとの設計

### 5-1. 著作権の基本

- **見本①「これは著作物？」カード（めくり式）**：小説の文章、スマホ写真、ソースコード、事実（売上の数字）、アイデア、ありふれた短文、キャッチコピー、文字だけのロゴ、書体（フォントのデザイン）、プロンプト1回のAI画像、料理のレシピ、データベース、地図。○ / △ / × と理由。
  - 根拠：著作権法 第2条1項1号（定義）、第10条（例示と第3項：プログラム言語・規約・解法は対象外）、第12条の2（データベース）、ゴナ書体事件（最判 2000年9月）。
- **見本②保護期間の計算機**：種類（個人の作品／団体名義／映画）と年を選ぶと、保護の終わる年と「あと何年」を表示。
  - ルール：死後（公表後）70年、暦年主義（第57条）。2018年12月30日の延長前に切れていたもの（1967年以前に死亡など）は復活しない。映画は2004年延長、1953年公表までは終了。戦時加算は注記のみ。
- **言葉**：著作物、著作者、無方式主義（©表記は不要）、著作権（財産権の内訳）、著作者人格権（譲渡できない）、職務著作、著作隣接権、二次的著作物、パブリックドメイン、侵害の2条件（類似性・依拠性）、権利が制限される場面（私的使用・写り込み・情報解析・引用・教育）、侵害したときの責任（差止・損害賠償・刑事罰＝2025年6月から「拘禁刑」）。

### 5-2. 他人の作品を使う

- **見本①引用の要件チェッカー**：6つの条件（公表済み・必要性・主従・明瞭区別・出所明示・改変しない）をチェックすると判定と足りない条件を表示。正しい引用の HTML（`<blockquote>`＋`<cite>`）の見本付き。根拠：第32条・第48条、パロディ・モンタージュ事件（最判 1980年）。
- **見本②「これ使っていい？」判定**：ケースを読んで ○ / △ / × を予想 → 答えと理由。拾った画像、公式の埋め込み、リンク、歌詞の全文・一部、キャラクターのアイコン、ファンアート、スクリーンショット、公式サイトの文章、フリー素材でロゴ、古い名画の写真、ライセンスのないコード。
- **言葉**：引用と転載、リンク、埋め込み、スクリーンショット、二次創作・ガイドライン、パロディ、オマージュとトレース、「フリー素材」の意味、商用利用、改変、再配布、利用許諾（ライセンス）、権利者への問い合わせ方。

### 5-3. OSSライセンス

- **見本①ライセンス比較**：MIT / Apache-2.0 / BSD-3-Clause / MPL-2.0 / LGPL-3.0 / GPL-3.0 / AGPL-3.0 / CC0・Unlicense / ライセンスなし を切り替え、「できること・条件・制限」を表示（choosealicense.com の分類に合わせる）。
- **見本②使い方別の義務チェッカー**：ライセンス × 使い方（アプリを配る／ブラウザに JS を配信／サーバーの中だけ／自分だけ）× 改変の有無 → やるべきことの一覧。GPL の「配布」と AGPL の「ネット経由の提供」の違いを体験できるようにする。
- **言葉**：OSS、パーミッシブとコピーレフト、各ライセンス、SPDX 識別子、デュアルライセンス、ライセンスの互換性、NOTICE、サードパーティーの表示、ライセンスなし（GitHub の公開リポジトリでも使えない）、依存パッケージのライセンス確認コマンド、ソースコードの「コピペ」。
- **表**：主なライセンスの早見（条件・向いている用途・有名な例）。

### 5-4. 自分の作品に付ける

- **見本①質問で選ぶチャート**：何を公開？（コード／文章・画像／フォント）→ 改良版も公開してほしい？ → 条件は少なく？ … とたどってライセンスを提案。
- **見本②LICENSE・表記メーカー**：MIT の全文（年・名前入り）、CC BY 4.0・CC0 の README 用表記、`package.json` の `license`、ファイル先頭の SPDX ヘッダー。コピーボタン付き。
- **言葉**：付けないとどうなるか、LICENSE ファイルの置き場所、著作権者の名前（ハンドル名でよい）、コードと文章で別ライセンス、商標（名前・ロゴ）は別、コントリビューション（DCO・CLA）、ライセンスの変更、利用規約との違い。

### 5-5. 素材・フォント・音楽

- **見本①クレジット表記メーカー**：作品名・作者・出典URL・ライセンス・改変の有無を入れると、TASL（Title / Author / Source / License）形式の表記と HTML を作る。
- **見本②規約の読み方**：架空の素材サイト規約で、「商用利用」「クレジット」「改変」「禁止事項」「再配布」「AI関連」の部分を光らせて説明。
- **言葉**：素材サイト規約の確認点、写真の人物・建物（モデルリリース）、アイコンのライセンス、Google Fonts と SIL OFL、商用フォントの利用範囲、音楽（作詞作曲＋録音の権利）、BGM と動画サイト、効果音、3Dモデル、AI生成素材の扱い、ストックフォトのライセンス、他社のロゴ。
- **表**：素材の種類ごとの確認ポイント。

### 5-6. AIと著作権

- **見本①2つの段階**：「開発・学習」と「生成・利用」でルールが違う（文化庁「AIと著作権に関する考え方について」2024年3月）。手順送り。
- **見本②似ている × 元を使った**：生成物が既存の作品に似ているか、元の作品を入力・指定したか／学習データに入っていたか、を切り替えて侵害の可能性を表示。
- **見本③人の関わりと著作物性**：プロンプト1回 → 詳しい指示 → 何度も生成して選ぶ → 加筆修正 → 自分の絵を元に、と段階を動かして「著作物になりうるか」を表示。
- **言葉**：第30条の4、享受目的、RAG、学習を拒否する手段（robots.txt など）、AI生成物の著作物性、AIサービスの利用規約（出力の権利・入力の扱い）、「〇〇風」のプロンプト、i2i、AIが書いたコードとOSS、AI生成の表示（各サービスのルール・C2PA）、声と顔（2026年9月 東京地裁の判断・報道）、海外の動き（EU AI Act 第50条・米国著作権局の報告書）、日本の AI推進法（2025年）、国内の訴訟（報道）。

### 5-7. 個人情報・肖像・商標

- **見本「公開して大丈夫？」判定**：友だちの写真、写り込み、有名人の写真を広告に、有名人の声をAIで、顧客情報をAIに貼る、有名ブランドに似たアプリ名、自作アプリの名前、アクセス解析、問い合わせフォーム、AIで作った架空の顔。
- **言葉**：個人情報・個人データ、利用目的、第三者提供、安全管理、漏えい時の報告、2026年の改正（課徴金の新設、2026年7月成立・報道）、プライバシーポリシー、外部送信規律（2023年6月〜）、Cookie、肖像権、パブリシティ権（最判 2012年2月）、商標権と J-PlatPat、不正競争防止法、名誉毀損・プライバシー侵害、子どもの情報、利用規約。

### 5-8. 公開前チェックと困ったとき

- **見本「指摘・削除依頼が来たら」手順送り**：あわてて消さない／内容と相手を確かめる／一時非公開／記録を残す／専門家に相談／返事。
- **チェックリスト（保存されるチェック）**：依存パッケージのライセンス、サードパーティーの表示、素材の規約とクレジット、AI生成物の確認、写っている人、個人情報、アプリ名の商標、LICENSE と README、プライバシーポリシー、秘密の値。
- **表**：相談先（知財総合支援窓口、個人情報保護委員会の相談ダイヤル、法テラス、弁護士、各サービスの窓口）。
- **AIへの頼み方**：規約の要約、ライセンス一覧の作成、クレジット一覧、リスクの洗い出し。「AIの法律の答えは必ず確認する」を明記。

## 6. 見本の部品（この辞典で新しく作るもの）

| 部品 | 使う所 | 動き |
|---|---|---|
| めくりカード | 著作物？ | 押すと ○△× と理由 |
| 判定クイズ（judge） | 使っていい？／公開して大丈夫？ | ○△× を選ぶ → 答えと理由・確かめ方、正解数 |
| チェッカー | 引用の要件 | チェックで判定が変わる |
| 質問チャート（tree） | ライセンス選び | 選択肢をたどる、戻る・最初から |
| 生成フォーム | LICENSE・クレジット | 入力 → 文面プレビュー → コピー |
| 部位の強調（anat） | 規約の読み方 | ボタンで該当箇所を光らせる |
| 2×2 判定 | 類似性×依拠性 | 切り替えでマスが光る |

## 8. 確認方法

- 幅 320px / 1000px で全タブのはみ出し・エラーなし、全見本のボタンを操作
- 計算・判定の中身（保護期間、義務チェッカー）を条文・ライセンス本文と照らして確認
- 「時点」「報道によると」の付け忘れがないか、日付を含む記述を一覧して確認

## 9. 定期点検の対象（変わりやすい内容）

AIと著作権の公的文書・判決、個人情報保護法の改正の施行日、EU AI Act の適用時期、各AIサービスの利用規約、素材サイト・フォントの規約。半年ごとを目安に見直す。
